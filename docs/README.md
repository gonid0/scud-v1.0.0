## Как читать

0. Для общего понимания системы — `PROJECT_OVERVIEW.md` (карта верхнего уровня).
1. **Затем — `00_shared_protocol (1).md`**. Это единый источник правды по форматам и криптографии. Его менять нельзя без синхронного обновления всех трёх реализаций.
2. Затем — специализированное ТЗ.

## Архитектура системы (краткое напоминание)

```
    [Server]
       │
       │ HTTPS (online only when user wants)
       ▼
    [Android]
       │
       │ NFC (physical tap)
       ▼
    [Reader]
       │
       │ GPIO
       ▼
    [Lock]
```

**Принципиальное свойство:** Reader никогда не выходит в интернет. Android выступает data-mule'ом между сервером и ридером. Обмен между Reader и Android — через NFC HCE.

Ключевые объекты:
- **issued_key** — подписанный сервером пропуск на конкретный телефон на конкретный ридер.
- **filter_package** — подписанный сервером bloom-фильтр отзывов + whitelist ложноположительных.
- **local_blacklist** — локальный список отозванных ключей на ридере, доставляется на сервер через телефон.

## Последовательность разработки (рекомендуемая)

1. **Backend** — базовый сервис, миграции, auth, endpoints. Без этого нельзя проверить остальное.
2. **Android** — можно параллельно с backend с mock-сервером.
3. **Firmware** — последним. До него нужен хотя бы один работающий телефон с приложением, чтобы отладить HCE-обмен.

Provisioning-процедура для ридера (генерация ключей, прошивка server_pubkey) описана в `ESP32/docs/02_firmware_spec (1).md` как отдельная утилита.
