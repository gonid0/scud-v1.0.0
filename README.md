# SCUD — самостоятельно-хостируемая офлайн-СКУД · **v1.0.0**

**SCUD** — система контроля и управления доступом, работающая **без постоянной связи ридеров с сервером**.
Ридеры (ESP32) автономны; состояние между сервером и ридерами переносит **телефон-курьер** (мобильное
приложение): вниз — подписанные сервером bloom-фильтры отзыва/выдачи, вверх — подписанные ридером квитанции
о проходе. Все четыре стороны системы реализованы самостоятельно, поверх **байт-точного криптопротокола**,
сверяемого золотым корпусом векторов между тремя независимыми реализациями.

> Дипломный проект (ВКР). Версия **1.0.0** — функционально завершён; единственный явно открытый пункт —
> **батарейный режим** (энергосбережение + поддержка CLRC663), оформленный как roadmap в
> [`docs/13_power_hal_architecture.md`](docs/13_power_hal_architecture.md).

## Ключевые свойства

- **Офлайн-доверие:** ридер не онлайн; ничего не подделать — фильтр подписан ключом сервера, квитанция — ключом ридера, ACCESS — ключом телефона + одноразовый nonce, привязанный к `reader_id`.
- **State-sync через курьера:** любой сотрудник с телефоном переносит обновления — больше трафика у двери = быстрее распространение отзывов. Консистентность **eventual** (окно отзыва до ближайшего тапа курьера).
- **Byte-exact протокол:** один корпус векторов (`docs/test_vectors/protocol_v1.json`) сверяется в Backend (Python), Android (Kotlin) и firmware (C++) с тремя независимыми крипто-библиотеками — гарантия, что реализации совпадают до байта.
- **Параметризация ридеров:** серверные профили (`hardware_class` + overrides + bounds + резолвер) → идемпотентный `SET-*`-скрипт, проигрываемый провижнером (`docs/11`).

## Roadmap (единственный открытый 1.0-пункт)

**Батарейный/автономный режим.** Сейчас ридер всегда на полной мощности (нет сна, NFC-поле активно).
Финальная архитектура энергосбережения — HAL (`INfcFrontend`/`IRtc`), драйвер **CLRC663** (true LPCD,
wake-on-card с выключенным полем), light/deep-sleep с пробуждением по NFC-IRQ/RTC, два power-профиля —
спроектирована в [`docs/13_power_hal_architecture.md`](docs/13_power_hal_architecture.md) (roadmap RM-0…RM-8).
